## 面向未来与实用性

为了让你编写的内容适用于资源水平各异的队伍，并在未来仍然有效，目标不应是广而浅，而应是深入讲解，帮助学生理解概念背后的基础原理，使他们能够将这些原理应用到自身的独特情况中。优缺点取决于具体情境，而基础原理具有普适性。

同时，为避免造成困惑，不应纳入队伍难以获取和/或不常使用的内容，例如整块铝材加工的底盘和球形驱动。

另一方面，加入只有实际制造后才能发现的小细节，往往能帮到所有人（例如用电工胶带固定猫舌防滑带，避免其剥落）。

### 为什么这很重要？

1. 我们无需为学生分析每一件事的优缺点来替他们做决定。新产品不断出现；让学生掌握相关能力，能使他们针对自身情况找到他人未曾想到的创新解决方案。

2. 这样一来，即使我们不直接说明，学生也能理解队伍为什么会做出某项决策，并自行判断其中的权衡。

3. 这能显著降低面向未来和持续维护所需的工作量。如果主流趋势发生变化，为保持竞争力而重写各个小节会非常耗时。即使项目停止且不再维护，这些信息仍能在更长时间内保持实用。

4. 这些小细节往往正是高度可靠的成功机器人与其他机器人之间的经验差距所在。它们能帮助缺乏经验的队伍，也能减少资深设计导师的审核工作量。

### 为了让这项工作更容易，下面提供几个建议：

1. 通常可以为每个概念找到两个极端，使其更直观。（例如比较 Stealth 轮与黄铜飞轮的转动惯量。）

2. 可以寻找一两个顶尖队伍的应用案例，并分析其决策涉及哪些基本权衡。这有助于学习者理解各个概念之间的联系，也同样适用于机构示例。

3. “如何用 CAD 建模某物”以及现实中的细微差别，对某些应用非常有用。例如连杆机构的草图绘制，或根据载荷确定张紧器位置。

## 受 gm0 风格指南启发

不要使用绝对化表述。

- 只有西斯才会如此绝对
- 使用优缺点列表比较不同方案
- 解释某件事为什么好或不好
  - 例如，我们都知道固定轴枢轴通常优于转轴枢轴。但不要只说前者更好，而应说明：“固定轴具有更大的截面二次矩，因为扭矩会直接传递到零件上。因此，枢轴会坚固得多，也更不容易损坏。”
  - 同样，我们知道 Kraken 电机通常表现良好，但应解释其原因。例如：“我们建议在传动系统上使用 Kraken，因为它们是扭矩极高的电机，可以提升加速度。此外，它们集成了 Talon FX 电机控制器，更便于布线；其高分辨率编码器也有助于提高舵轮里程计的精度。请注意，Kraken 电机目前还不能直接兼容原装 REV MAXSwerve 模块，需要使用 WCP 的额外适配器才能与其他现有模块连接。”
- 仍应强调队伍可以自由探索和创新，但也要帮助他们建立切合实际的预期（见下一点）

FRCDesign.org 是一份**从竞技角度出发**的指南。

- 尽量不收录效果不佳且不常用的方案；如果某个方案很流行，则值得说明其缺点（例如坦克式底盘与麦克纳姆轮底盘：介绍相对常见且简单的坦克式底盘很合理；但在舵轮时代，几乎没有推动力或牵引力的麦克纳姆轮底盘已不再合理。）
- 尽量减少主观意见。对于没有亲身经验的内容，尽可能不要以权威口吻下定论

请记住，FRC 的设计趋势只是暂时的，会不断变化。

- 某个方案在一个赛季流行，并不意味着它就是终极答案。WCD 和钣金上层结构也曾风靡一时，但这并不代表本指南就应推荐它们。请尽力思考某项方案为何流行，以及它在设计、功能和实施方面实际带来了哪些优势。

### 社交分享卡片

社交分享卡片是页面分享到 Discord 或其他应用时显示的预览图片。它们会根据每个页面的 `title` 和 `description` 自动生成，因此大多数贡献者无需进行特殊处理。

机构示例页面还可以在 frontmatter 中包含 `image`。它会使用与网站其他部分相同的绿色机构卡片样式：

```yaml
---
title: 1678's Rapid React Shooter
description: A ball shooter with rack gear actuated hood
image: ./img/1678_2022_shooter.webp
---
```

如果卡片需要使用不同于页面标题或描述的文字，请在页面 frontmatter 中添加一个简短的 `socialCard` 块：

```yaml
---
title: Shooter Mechanisms
description: Examples and design notes for FRC shooter mechanisms
socialCard:
  title: Shooter Mechanisms
  description: Study proven FRC shooter designs and the tradeoffs behind them.
  image: ./img/1678_2022_shooter.webp
---
```

对于电梯等纵向较长的机构，请在 `socialCard` 中使用 `layout: mechanism-tall`。大多数机构页面可以使用默认的 `mechanism-wide` 布局。

要禁用某个页面的卡片，请使用：

```yaml
---
socialCard: false
---
```

如果要在本地重新生成预览图片，请运行 `npm run social-cards`。正常的网站构建过程也会自动重新生成这些图片。

### 术语表条目

术语表条目位于 `src/data/glossary.ts` 中。当某个单词、首字母缩写、供应商简称或 FRC 设计短语需要在全站提供简短定义时，请在该文件中添加新条目。

每个条目采用以下格式：

```ts
{
  term: "COTS",
  definition: "Commercial Off the Shelf - Parts you can buy from a vendor"
}
```

添加术语时：

1. 将其放入 `glossaryTerms` 数组中最相关的版块，例如供应商、收集机构类型、零件、电子设备或设计概念。
2. `term` 应保持为读者最可能在内容中看到的准确拼写。匹配不区分大小写，因此 `COTS` 也会匹配 `cots`。
3. `definition` 应足够简短，以便用作悬停提示。通常一句话最合适。
4. 只有贡献者确实会同时使用两种写法时，才将不同拼写作为独立条目添加，例如 `Poly` 和 `PC`。
5. 创建拉取请求前运行 `npm run build`，确保术语表数据仍可正常编译。

术语表中的术语会在页面文本中自动添加下划线，并在悬停时显示其定义。系统按完整术语匹配，因此请避免添加非常常见的短词，以免在无关页面中产生干扰阅读的高亮。

公开术语表页面 `/resources/glossary/` 在 `src/content/docs/resources/glossary.mdx` 中单独编写。如果新术语需要显示在可见的术语表列表中，也请更新该页面。

### 品牌规范

请尽可能遵守品牌规范。

- 遵守 *FIRST* 商标指南，可在[此处](https://www.firstinspires.org/sites/default/files/uploads/resource_library/UseofUSFIRSTandLEGOGroupTrademarksandCopyrightedMaterials.pdf)查看
- 页面中首次出现 *FIRST* 和 FRC 时，应包含注册商标符号（例如 *FIRST®*）
- 名称 *FIRST* 必须始终全部大写并使用斜体
- 不要对 *FIRST* 名称使用所有格形式（例如 FIRST's）
- 此规则同样适用于队伍名称：请按照官方拼写书写
- 如果不确定队伍名称的拼写，请查询 [The Blue Alliance](https://www.thebluealliance.com/)

写作时，如果使用“你”能让表达更自然，可以使用，但应尽量避免过度使用。
